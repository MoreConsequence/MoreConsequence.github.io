# mini-lsm: 写放大 / 读放大 / 空间放大的字节账模拟器

`main.go` 是一个可运行的内存版迷你 LSM（教学原型，不碰真实磁盘）：
memtable（满就落盘）→ L0 / tier0 → 逐级合并（compaction）。键带全局自增 seq，
同键保留最新版本，合并时旧版本被丢弃——"同一份数据被重写多遍"就是写放大的来源。

放大率的定义与磁盘时序无关，所以用字节账 + 随机 IO 探测次数就能算：

- **写放大** = (flush 输出字节 + 全部 compaction 输出字节) / 用户写入字节
- **读放大** = 一次点查在 SST 上做的随机 IO 次数（键范围判断与 bloom 判断是内存操作，不计 IO）
- **空间放大** = 运行期磁盘峰值字节 / 逻辑存活字节

键模型：唯一键是 `[0, 2*num)` 里的偶数；点查的"不存在"键取奇数，保证落在所有 SST
的键范围内（不触发范围剪枝），测的才是 bloom 而不是巧合。

bloom 假阳性率不拍脑袋，由公式推出：m/n 每键位数 + k 个哈希，
`p = (1 - e^{-k/(m/n)})^k`（默认 m/n=10、k=7 → 约 0.82%）。

## 运行（在仓库根目录）

```bash
go run ./mini-lsm                      # Leveled 与 Size-Tiered 各跑一遍，打对比表
go run ./mini-lsm -ratio 4             # 调 T（每层尺寸比）
go run ./mini-lsm -bits-per-key 20     # 调 bloom 每键位数，看读放大怎么变
go run ./mini-lsm -num 300000 -writes 400000 -mem 6000 -sweep   # 扫 T 的三张曲线表
go run ./mini-lsm -num 300000 -writes 400000 -mem 6000 -sweep -csv   # 输出 CSV
```

常用参数：`-num` 唯一键数、`-writes` 总写次数（含更新）、`-mem` memtable 条目数、
`-ratio` T、`-levels` 最大层级（0=自适应，数据量决定实际层数）、`-l0` L0 合并阈值、
`-seed` 随机种子（固定保证可复现）。`-policy leveled|sizetiered` 单跑某策略。

## 预期结论（机制层面，非本机基准）

- Leveled：写放大明显高于 Size-Tiered（每字节每层重写一次，末层重叠重写更贵）；
  但层内键域不相交，点查每层最多一次随机 IO，读放大低；空间放大接近 1。
- Size-Tiered：写放大低（同层攒够 T 份才合成更大的 run，代价随层数而非 T 增长），
  但 run 互相重叠，点查要翻多个 run（读放大高），空间放大也高（旧版本滞留）。
- bloom：把"不存在"键的读放大从 O(层数) 压到约 假阳性率×层数。
- T 变大 → 同数据量下层数变少，写放大 / 读放大的层数项变小；但每层合并的
  "下一层重叠重写"变大，Size-Tiered 的空间放大 O(T) 变大。

注意本模拟器的局限（文章里有展开）：合并很勤快、每键只保留最新版本，所以
Size-Tiered 的空间放大通常远低于论文上界 O(T)；要看到更大的空间放大，
需要增加更新比例、让旧版本在更多 run 里滞留。
