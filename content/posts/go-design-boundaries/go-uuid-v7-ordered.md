**TL;DR：** Go 1.27 标准库 `uuid`（RFC 9562）提供 `NewV4`/`NewV7`：v7 前 48 位是 unix 毫秒，隔 15ms 生成的两个必有序（`Compare < 0`，已验证）；但同一毫秒内后缀随机，**有序不等于严格单调**。4 测试全过。选型结论：主键/索引键优先 v7（时间局部性对 B-tree 友好），仅需不透明令牌时 v4 更少信息泄漏。

## 一、位布局：版本号与变体一眼可辨

```text
v4=d88a4942-fc23-4505-96f9-1f98af8373ee  → byte6 高 4 位 = 0100
v7=01a09bcc-9619-7e18-bcdc-8bb6d61ad5cc  → byte6 高 4 位 = 0111，开头即毫秒时间戳
```

v7 的可读性是附赠的：出问题翻日志时，v7 主键自带大致时间，不用再 join 创建时间列。

## 二、合同

| 维度 | 保证 | 不保证 | 调用者仍负责 |
| --- | --- | --- | --- |
| 唯一性 | CSPRNG 熵源，万级零碰撞（已测） | 数学上不碰撞 | 跨系统合并时仍保留冲突处理 |
| v7 有序 | 跨毫秒单调（已测，15ms 间隔） | 同毫秒单调（后缀随机） | 需严格单调用 DB 序列/雪花 |
| 格式 | 8-4-4-4-12，`Parse` 往返恒等，非法拒绝 | 大小写/花括号兼容（入库前统一） | 入口归一化 |
| 随机性 | v4/v7 随机部分 CSPRNG | v7 时间戳公开（可推测生成速率） | 对外暴露的 ID 是否泄漏业务量，v4 更稳 |

## 三、实测

`experiments/go127-uuid/uuid_test.go`（独立 go.mod），原始输出 `evidence/go-uuid-v7/2026-09-14-local/run.out`，4 PASS：版本位/变体位、往返 + 非法拒绝、万级唯一性、跨毫秒有序。

## 四、选型：一行

对外 ID 要不可推测 → v4；数据库主键/按时间查 → v7；要严格单调 → 都不是，用序列。v7 替代第三方 `google/uuid` 的迁移测试就是本文 4 测试的形状。

## 五、证据卡与边界

| 字段 | 内容 |
| --- | --- |
| 环境 | Darwin arm64，go1.27.1，stdlib only |
| 不支持结论 | 跨版本字节一致性、B-tree 真实插入性能（需目标 DB 实测）、v1/v6 历史版本 |
