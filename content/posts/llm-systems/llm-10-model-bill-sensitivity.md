**TL;DR：** 2026 年 9 月第一周，Claude Fable 5.1、GPT-6 Astra 同标输入 $10 / 输出 $50 每百万 token，Gemini 3.8 Flash 标 $0.75/$3.75，Muse Spark 1.3 标 $1.25/$4.25——但标价只定了斜率。在固定 workload（每任务 8 轮、前缀 40K、1000 任务/日）下，纯数学模型算出月账单从 $4,608 到 $49,200，差 **10.7 倍**；同一价格内，输出膨胀 3x 让账单 ×1.7，缓存命中从 90% 掉到 50% 让账单 ×1.9。价格数字是 2026-09-13 第三方 tracker 快照的假设输入（见第六节边界），本文真正可复现的结论是四个乘数的排序。

本文是 [token 经济学](/writing/llm-token-economics) 的续篇。前文用 GPT-4.1 单一价格证明了“prompt 结构决定账单数量级”（裸 prompt $744/月 vs 不缓存 21K 输入 $13,644/月，18.3 倍）；本文固定 prompt 结构，只换价格结构，回答：**同样的 workload，账单差是从哪里来的？**

## 一、完整路径：一次任务的钱花在哪四段

```text
每轮：新增输入 × 输入价
    ＋ 稳定前缀 × 命中率 × 缓存价
    ＋ 稳定前缀 × (1−命中率) × 输入价
    ＋ 本轮输出 × 输出价
    （×8 轮 ×1000 任务/日 ×30 天）
```

四个乘数按影响力排序（本 workload 下）：**输出价 × 输出量 ＞ 缓存命中率 ＞ 输入价 ＞ 长上下文附加费**（后者只在超 200K 上下文生效，平时为 1）。

## 二、合同：标价保证什么、不保证什么

| 标价项 | 保证 | 不保证 | 调用者仍负责 |
| --- | --- | --- | --- |
| 输入/输出单价 | 按 token 计量的斜率 | 任务总 token（由你的 prompt 与模型话痨程度定） | 压输出长度、压前缀体量 |
| cache-read 折扣 | 命中前缀按折扣价计 | 前缀能命中（并行冷启动、频繁改系统提示都会打散命中） | 前缀稳定性设计、命中率观测 |
| Batch 5 折 | 离线任务半价 | 延迟（Batch 按小时级返回） | 区分在线/离线链路 |
| 长上下文门限 | 门限外才加价 | 你的任务不越线（整仓上下文一次就越线） | 上下文预算与截断策略 |

## 三、实测：同一 workload，四档价格

workload：8 轮/任务，前缀 40K + 每轮新增 6K，输出 1.2K/轮，缓存命中 90%，1000 任务/日。脚本 `experiments/llm-bill-sensitivity/bill.mjs`，零依赖，`node experiments/llm-bill-sensitivity/bill.mjs` 可重跑，原始输出 `evidence/llm-bill-sensitivity/2026-09-13-local/run.out`。

```text
A flagship 10/50 + cache0.25       单任务 $1.352 | 月 $40560
B flagship 10/50 + cache1.25       单任务 $1.640 | 月 $49200
C value 1.25/4.25 + cache0.3       单任务 $0.227 | 月 $6816
D flash 0.75/3.75 + cache0.2       单任务 $0.154 | 月 $4608
最高/最低 = 10.7x（同为“能跑”，月账单差一个数量级）
```

手算复核 A 基线：新增 6K×$10/M×8 = $0.48；前缀命中 36K×$0.25/M×8 = $0.072；前缀未命中 4K×$10/M×8 = $0.32；输出 1.2K×$50/M×8 = $0.48；合计 $1.352，与脚本一致。

注意 A 与 B 标价同为 $10/$50，月账单差 $8,640——差额全部来自 cache-read 一个数字（$0.25 vs $1.25）。**比价时只看输入/输出两栏，等于没看。**

## 四、同一价格内：输出膨胀与命中率才是内鬼

```text
基线(90%命中,精简输出)   单任务 $1.352 | 月 $40560
输出膨胀3x               单任务 $2.312 | 月 $69360 (1.7x)
缓存命中→50%              单任务 $2.600 | 月 $78000 (1.9x)
```

两个反直觉点：

1. 输出单价是输入的 5 倍（$50 vs $10），所以模型“多说两句”的杀伤力远大于输入涨价。推理机型的 chain-of-thought 越长，这一项越主导——选型时要对比的是**每成功任务的输出 token 数**，不是每百万 token 单价。
2. 缓存命中从 90% 掉到 50%，账单接近翻倍。而命中率恰恰是最不稳定的：并行冷启动（多个请求同时带着冷前缀到达，互相 Cant 命中）、每次微调系统提示、工具回包污染前缀，都会把它打散。9 月初的 CloudZero 盘点提到并行冷启动下命中率可跌到个位数——这就是“假设 90%”与“线上 50%”的差，$38,440/月。

## 五、长上下文附加费：平时为 1，越线即 ×1.7

整仓级前缀 240K（×6）的对照：A 基线单任务 $3.312，加“超 200K 部分输入价 ×2”后 $5.712（1.72x）。而常规 88K 峰值 workload 根本不触发 200K 线。结论是条件性的：**做 coding agent 且喂整仓上下文，选型必须先问门限；做短任务，这一项直接忽略。**

## 六、证据卡与边界

| 字段 | 内容 |
| --- | --- |
| 问题 | 同 workload 下，价格结构与用量习惯各自放大账单多少倍？ |
| 环境 | Darwin arm64，Node v24.19.0，零依赖纯算术 |
| 输入 | 固定 workload（8 轮/40K 前缀/6K 新增/1.2K 输出/90% 命中），四档假设价格 |
| 原始输出 | `evidence/llm-bill-sensitivity/2026-09-13-local/run.out`，A 基线手算复核一致 |
| 支持结论 | 四个乘数的排序与倍数（10.7x / 1.7x / 1.9x / 1.72x） |
| 不支持结论 | 任何真实账单：价格是第三方 tracker 快照的假设输入，不是官网报价；无真实供应商调用、无配额/TTL、无质量（成功率）维度 |

价格快照的发出方与日期：9 月 wave（Fable 5.1、Astra、Gemini 3.8 Flash、Muse Spark 1.3、Qwen3.8-Max 均 2026-09-01~03 发布）经第三方价格 tracker 汇总，2026-09-13 核对。**上线前必须按官网定价页重核**，价格、门限与 Batch 政策都可能已变。

## 七、结论：按 cost per successful task 选型

回到开头：同样的 $10/$50，账单差 10 倍，因为账单 = 单价 × 用量，而用量（输出长度、命中率、上下文体量）全在你手里。行动清单：先压输出（选话少的模型、限长），再保前缀命中（冻结系统提示、串行预热），再看 cache-read 栏，最后才对比输入单价。短任务忽略长上下文门限，整仓任务先问门限再谈单价。
