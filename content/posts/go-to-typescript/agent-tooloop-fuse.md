**TL;DR：** Agent 卡在“报错→重试→同样报错”时，步数预算拦不住（每步都“有进展”）。按失败签名熔断：同一签名连 3 次即停（`{outcome:"fused",steps:3}`），交替错误跑满 6 步不误伤，自愈第 3 步直接成功。4 断言全过。这是 backlog S2 的“工具死循环防护”落地：状态机扩展只需加一个签名窗口。

## 一、完整路径：一次死循环如何被拦下

```text
工具错(ERR_TIMEOUT) → 记签名[1]
  → 重试错(同签名) → [2]
  → 再错(同签名) → 满 3 → fused，附签名返回
vs 交替错(E1,E2,E1,E2…) → 窗口永不满 → 跑满预算
```

## 二、合同

| 维度 | 保证 | 不保证 | 调用者仍负责 |
| --- | --- | --- | --- |
| 检测 | 同签名连 N 次必停 | 慢漂移（签名渐变） | 签名归一化（去时间戳/数字） |
| 误伤 | 交替错误不触发 | 语义不同但签名相同 | 签名设计（工具名+错误类） |
| 熔断后 | 附签名，可定位 | 自动恢复 | 熔断后的降级/转人工 |

## 三、实测

`experiments/agent-fuse/fuse.mjs`，`evidence/agent-fuse/2026-09-14-local/run.out`，4 PASS。F1 的 steps=3 是关键：省下的不只是 3 步 token，是无限循环的尾部风险。

## 四、证据卡与边界

环境 Node v24.19.0，stub 工具确定性错误。不支持：真实模型错误分布、签名归一化策略、分布式多 agent 循环。
